runner began consuming predictions from the evidence-bound admission. The
workload blocks on subprocess sleeps and protocol I/O, so the speedup comes
from overlapping waits across heterogeneous runtimes, not from parallel CPU
computation.

## Worker-capacity sweep

`--workers 1` constrains the local-worker pool; it does **not** turn this
10-logical-CPU host into a single-core machine. It is a scheduler-capacity
control. Four workers cover the widest predicted layer, and eight workers add
capacity beyond every admitted fixture width.

Capacity one removes the concurrency benefit from every shape. In this run,
capacity eight does not materially improve on capacity four; that observation
is consistent with the static prediction containing no layer wider than four,
but static width is not a hard bound on the completion-driven dynamic frontier.
The width-one chain remains approximately 1× at every capacity.

## Analyzer and semantic checks

For each rendered fixture and worker setting, the harness first invoked the
co-built `olangc --target ir --explain-schedule`. It required exactly one v3
admission, one canonical digest binding, one v1 prediction whose admission
digest matched that binding, and internally consistent task layers. No manual
width/span table was consulted by the runner.

All 72 warmup or measured serial/graph pairs reported both:

- `semantic_equivalence=true`: identical canonical `ok`, type, and returned
  OValue JSON from the serial and graph executors; and
- `expected_output_match=true`: that same value matched the checked-in fixture
  result.

The raw transcript retains every pair's order and elapsed times, all 12
prediction summaries, all binary/runtime provenance fields, and every final
median and range.

## Interpretation and non-claims

This record demonstrates wait concurrency on a multicore machine. It neither
recreates nor claims a one-logical-CPU result, and it is not evidence of CPU
parallel computation. Worker capacity is not CPU affinity or a processor
reservation.

The analyzer predicts static hosted-task layers. It does not predict durations,
reserve CPU or memory, prove runtime readiness, choose observed placement, or
prove that a legal layer overlapped physically. The measurement validates the
prediction against this bounded fixture/runtime/machine combination.

Semantic equivalence covers returned values only. It excludes filesystem and
network effects, scope snapshots, traces, timing, and external-effect ordering.
The record does not widen `explicit-autonomous-unordered` into strict serial
effect equivalence and does not claim general application throughput or
scheduler optimality.
